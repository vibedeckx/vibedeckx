---
title: Preview a dev server
description: Open a dev server running on any of your connected machines, from any browser.
---

An agent often leaves a dev server running on the machine it works on. The **Preview** tab in a workspace lets you open that server in your own browser, even when the machine is a box in another room or a VM in the cloud, and even from your phone.

## Open a preview

1. In a workspace, open the **Preview** tab.
2. Pick the machine the server runs on and type its port (for example `3000`).
3. Click **Open**.

The page opens in a new tab at its own address, something like `https://k7f2qa.vdxpreview.dev`. Everything the page does, including live reload and sign-in state, works as it would on `localhost`.

Each machine and port you open is remembered as a **preview link** under the form. Reopen one from there, or remove it when you no longer need it.

## Keep the address

A preview address keeps working as long as the link exists. You can bookmark it or send it to another of your own devices.

Opening it later asks your browser to prove it is you: if you are not signed in to Vibedeckx in that browser, you are sent to Vibedeckx to sign in and then straight back to the preview. The preview sign-in lasts twelve hours.

The address is private to your account. Someone else who finds it sees a sign-in page, not your app.

## What you need

- The machine must be connected (it shows **online** in **Remote Servers**) and run a recent worker. An older worker is refused with a message asking you to update it.
- The dev server must listen on the machine itself (`localhost`). Vibedeckx reaches it over the machine's existing connection; no port on that machine is opened to the internet.

<Callout type="info">
  The preview opens in a new tab rather than inside Vibedeckx on purpose. Each preview has its own address, separate from Vibedeckx and from every other preview, so a page you preview can never read your Vibedeckx session or another preview's data.
</Callout>

## Self-hosting

Previews need a domain of their own, separate from the one the app runs on, with a wildcard DNS record and certificate pointing at your server:

```bash
vibedeckx --auth --preview-host vdxpreview.example.com
```

or set `VIBEDECKX_PREVIEW_HOST`. Without it, the Preview tab explains that previews are off. Running without `--auth` on your own computer needs no setup: previews use `preview.localhost`, which browsers resolve to your machine.
