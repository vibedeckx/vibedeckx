---
title: Connect a machine
description: Run agent sessions on your own hardware from vibedeckx.dev.
---

Agents run on machines you connect. The machine dials out to the Vibedeckx server, so it needs no open ports or public address.

In **Settings → Remote Servers**, add a server for the machine and open its connect token. Copy the command shown there and run it on that machine — it looks like:

```bash
npx vibedeckx connect --connect-to https://vibedeckx.dev --token <token>
```

That runs the worker in your terminal until you close it. For a machine that should stay connected, install it as a service instead.

## Keep it running (Linux and macOS)

```bash
npx vibedeckx@latest connect install-service --connect-to https://vibedeckx.dev
```

It asks for the token (input is hidden), then installs the worker as a service of your user: **systemd** on Linux, **launchd** on macOS. The worker then:

- starts when the machine boots,
- restarts by itself if it crashes or is killed,
- keeps its own copy of Node and the worker, so later Node upgrades on the machine don't affect it.

To pass the token without typing it, use `--token-file <path>` or `--token-stdin`. Avoid `--token` on the command line: other users on the machine can see it in the process list.

<Callout title="Linux: start at boot">
  systemd user services only start at boot when lingering is enabled for your user. `install-service` turns it on when it can; otherwise it prints the command, typically `sudo loginctl enable-linger $USER`.
</Callout>

<Callout title="macOS: after login">
  A launchd agent starts when you log in. For an unattended Mac, enable automatic login.
</Callout>

### Managing the worker

`install-service` also creates a `vibedeckx` command in `~/.local/bin` that runs the installed worker directly, without npx or a download. If `~/.local/bin` is not on your `PATH`, the installer tells you what to add.

| Command | What it does |
|---|---|
| `vibedeckx connect status` | Shows whether the worker is running and connected, and how to fix it if not |
| `vibedeckx connect stop` | Stops it until the next boot or `start` |
| `vibedeckx connect start` | Starts it again |
| `vibedeckx connect restart` | Restarts it |
| `vibedeckx connect disable` | Stops it and keeps it off across reboots |
| `vibedeckx connect enable` | Turns auto-start back on and starts it |
| `vibedeckx connect uninstall-service` | Removes the service and the `vibedeckx` command; your data and token are kept |

`status` only looks at this machine. Add `--check-update` to also check for a newer version.

### Changing the token

If you rotate the token in **Settings → Remote Servers**, save the new one on the machine:

```bash
vibedeckx connect setup
```

It asks for the new token (press Enter to keep the current one). A running worker picks it up without a restart. While the token is invalid, `connect status` shows `auth-failed`.

If the machine should start serving a different remote server, run `connect setup --force` with that server's token, then `connect restart`. Without `--force` the worker refuses a token that belongs to another server and shows `blocked`.
